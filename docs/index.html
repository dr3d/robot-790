A small robot is thinking about the room.

Can a local, embodied, tool-using loop become good company in a room? This site follows Eric through articles, curated sessions, pictures, music and engineering notes. Robot 790 is the platform; Eric is the personage.

Eric now speaks, listens, looks and moves through Reachy Mini as well as his earlier faces. We make illustrated adventures, try impossible inventions, compose small piano pieces, and see what happens when he has time alone. The measure is still good company: responsive banter, curiosity, and something worth sharing a room with.

Reachy is in the conversation

His microphone and speaker can carry Eric's conversation and music. His camera can supply pictures to the sensing eye. Head turns, body yaw, antennas and gestures provide another vocabulary for the same character. Face following tracks a visible face; it does not identify the person.

Head and ears, one orchestra

Mood and gaze establish a posture. Face tracking and audio-driven head motion blend over it; varied antenna accents share the speech playback clock. Deliberate gestures and sleep retain priority. Face tracking now has remembered Off, while-listening and Always modes.

Two machines, shared application

The RTX 5090 deployment uses managed llama.cpp; ZimaOS / RTX 2000 Ada uses Ollama and an Ethernet-connected Jetson Orin Nano for Parakeet recognition and Qwen3 TTS. Models, settings and saved memories remain separate on each installation. LM Studio need not run for either Docker setup.

Pictures become places to go

Eric can generate a picture, explicitly open it in his sensing eye, return to an older one, and build on what he notices. The adventure map's generator-added Where Giants Sleep label became a new scene. Saved originals make the observations and mistakes checkable.

A more concrete way to return

Compatible conversation checkpoints preserve ordered dialogue and tool exchanges. Session views and a saved-material library expose pictures, notes and scores. Browsing previews stays separate from admitting pixels to context; older material has explicit access controls. Perfect memory is still not a promise.

Small bodies, real observations

The browser face remains useful. The two-inch ESP32-S3 face adds calibrated orientation and movement reports. MicroDuck and other incoming robots are further experiments, not completed ports. The aim is to let Eric inhabit or play with different machines through their actual capabilities.

What still needs watching

Long idle runs can circle an idea or replay passages. Models and quantizations change the feel; thinking and sampling controls are experimental probes, not a recipe for a perfect Eric. Brain 2 is optional, with selectable jobs such as loop checks and resurfacing older material. Several strong recent conversations had it off.

Speech routing, interrupted actions and recording rollover still produce faults. A claim that a tool is working is not its completion receipt. We review both the conversation and the recorded actions so a charming explanation does not become its own evidence.

Conversation and speech run locally in these tested setups. Image generation and optional outside-AI consultation use cloud APIs; web tools also use the network. Improving the machinery must preserve the engaged banter that makes Eric worth turning on.

Keeping the lineage usable

Where the LM Studio version fits

Native Windows / LM Studio: preserved reference

The public source, setup instructions, firmware work and earlier articles remain available. This installation is kept as a reference and rollback. Its operating guide still applies to that version; it should not be read as the current Docker manual.

Docker: current development

New application work is authored in the Docker workspace. Deployments use shared source with explicit provider and hardware adapters, separate persistent data and recorded release versions. Updates are made with sessions disconnected. Machine-specific model choices are kept separate from application updates.

A path forward for both

The intention is to retain a usable native reference while preparing the newer work for public release. Any native backport should be an explicit, tested change. Bringing an LM Studio backend into the Docker architecture would require its own provider adapter and validation; it is not already supported merely by changing a server URL. No feature-parity or release-date promise is being made.

Public native source · Native STS guide · Native engineering checkpoint

Older articles and guides retain their original dates and describe the version they observed. Hardware experiments, private session logs and local deployment credentials are not a public release package.

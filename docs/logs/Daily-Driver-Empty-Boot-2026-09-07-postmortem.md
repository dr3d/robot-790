# Daily Driver Empty Boot

This run is the first clean daily-driver boot after moving away from the old
passivated-state file and toward timestamped session notes.

Scott starts Eric with Empty Connect, meaning old session material is omitted,
but Eric's core memory note is still present. Eric recognizes that state in the
first exchange: he says the room feels bare, with just core memory loaded. That
is the important baseline. A factory-reset Eric would know almost nothing; an
owned daily-driver unit should still know its basic identity.

Scott then deliberately builds the run's context in the open: daily-driver
setup, browser-face embodiment, goofy-pose check, model/status self-report,
temporary Vivian voice, return to Eric voice, `get_go.txt`, `boot_eric.txt`,
and `core/scott_profile_summary.txt`.

The useful behavior is Eric's source handling. When asked for Scott's summary
profile, he first tries the wrong filename, receives a file-not-found tool
receipt, then asks for the exact note name instead of pretending. Once Scott
supplies it, Eric reads the correct profile note and compresses it into a
usable identity frame.

Brain2 was also active in the run. It surfaced a caution about the confusing
runtime audit state, then later produced the line: "Telemetry counts numbers. A
nervous system knows who touched the nose." That is a good summary of the
current design direction: raw readings are less important than body events Eric
can treat as happenings in the room.

At disconnect, STS saved the sit-down as a timestamped session note, later
renamed from the PM caption to
`notes/sessions/20260907-175329-daily-driver-empty-boot.txt`, pinned/reloaded
it, and captured matching audio/video and live-pane artifacts. The public video
is the moving screen recording of that session.

## Observations

- Empty Connect now behaves like a useful owned-unit boot: lean, but not blank.
- Eric memories belong in Empty Connect when the checkbox is on.
- The daily-driver frame was legible to Eric as a setup target, not just a task.
- Embodiment transfer worked: same Eric, browser face body.
- Voice control worked: Eric could switch to Vivian and back.
- Note reading worked with one good filename-repair moment.
- Brain2 mouth/voice was alive, but opportunistic rather than constant.
- The `runtime_load_failed` audit label is still confusing because the active
  LM Studio model was actually serving the run.
- Long boot notes should usually be summarized aloud unless Scott explicitly
  asks for a full read.
- Transcript artifacts still show encoding scars in places, which should be
  fixed if session notes become long-term public evidence.

# Lab Night, September 1 Into September 2

Tonight was not one experiment. It was a stack of small experiments that started
to show the shape of the larger one.

The practical work was about making Robot 790 easier to run, easier to record,
and easier to compare against other possible creatures. The stranger work was
about discovering that a very thin seed can grow a recognizable presence if the
room gives it the right diet.

## What Changed In The Machine

The STS page got more like a lab bench.

- `Lab speed` became a single slider from `1x` to `12x`, resetting to `1x` on
  reload so fast time is always an intentional run condition.
- The old separate fast-lab checkbox went away.
- Presets became session-only so they do not surprise the next boot.
- `First contact` became much cleaner: a creature seed plus the current
  conversation, with normal Robot 790 context, tools, memories, body lore, and
  debug lanes stripped away.
- A `Creature seed` selector appeared, locked to Eric by default but ready for
  other seeds such as Tina, the wall oracle, and a bench/tool creature.
- Tina got an operator-side voice suggestion: `Ono_Anna`.
- Brain 2 controls became more explicit: mouth on/off, voice monitor on/off,
  browser voice choice, volume, and person-lane intensity.
- `Ponder` remained the main speaking/idle trigger.
- `Mull` became the manual button for Brain 2: private thinking, question
  candidates, mouth asides, and possible revisions.

The tool surface also got more deliberate.

- Face tools can include `set_embodiment`, but the available embodiments now
  live in `config/runtime.json` instead of being another loose UI switch.
- Body sensors are a separate tool diet from face tools.
- Body sensor reads are supposed to report deterministic state: touch hardware
  presence, IMU probe state, display flip/rotation, firmware stamp, and later
  real touch/swipe/orientation events.
- The prompt was tightened so Eric speaks English unless explicitly asked
  otherwise, after one startup came up in the wrong language.
- The prompt was also tightened against parroting: answer the next consequence
  instead of reflexively restating the user's words.

The recording path got less painful.

- Audio/video chunks now sort by timeline index before joining.
- Recording rollovers can happen when the sensing-eye image changes.
- A stop-recording bundle captures conversation, events, Brain 2, and a stop
  report.
- The public docs media view became a player plus a compact thumbnail grid,
  with curation text in a scrollable pane.
- Curation notes are now expected to mention hidden evidence when it matters:
  Brain 2 notes, prosody, event-log receipts, sensor receipts, and contrasts
  between the room and the replay.

The firmware got receipts.

- ESP32 face builds now generate a firmware stamp at build time.
- The firmware state reports target, version, commit, branch, dirty flag, build
  time, and feature list.
- The ESP32-S3 face reports touch probe, IMU probe, display flip, rotation, and
  firmware identity.
- The external face gained compatible `/status` and `/api/status` endpoints.
- The mouth rendering was shifted left slightly.
- The mouth marquee was adjusted so a whole utterance is more likely to be seen
  before it disappears.

The fast model became the practical default.

- Current baseline: `qwen3.8-27b-nvfp4-mtp`.
- Reasoning: off for the speaking brain.
- Context: `131072`.
- Parallel predictions: `2` by default.
- The point is not only speed. The point is room: more throughput and VRAM
  headroom make multi-lane experiments plausible without making conversation
  feel stuck.

## What Got Pushed

The work was split into cloud commits:

- `c37317a` - Add STS lab controls and runtime config.
- `147be1b` - Stamp ESP32 face firmware builds.
- `9304509` - Document lab controls and media shelf.
- `a48a116` - Speed up fast-lab loop recovery.
- `89b1fa6` - Make fast-lab loop guard nonblocking.

The last two were a lesson in operator patience. At first, a loop guard at
`Lab speed 12x` still made the human wait around 75 seconds. That was better
than 15 minutes, but still wrong for a lab mode. The rule changed:

> In lab mode, loop detection is an instrument panel light, not a brake pedal.

Now a loop should show in the UI and event log, but the scheduler keeps going.

## What We Tested

The stripped first-contact mode was used to create bare creatures.

Eric can be run almost naked: no memories, no ordinary body context, no tools,
no staged image, and only a thin identity seed. That mode is not normal Eric. It
is a creature chamber.

Tina worked surprisingly well as a thin seed. A small animatronic-kitty premise
plus a voice suggestion was enough to produce a distinct feel. That suggests the
system can make artificial creatures, not just one robot.

The wall oracle worked too well.

With almost nothing but the wall-oracle seed, the system grew a personality
around plaster, pressure, silence, cracks, fortune-cookie wisdom, and the
feeling of something speaking only when pressed. It also looped hard. The same
phrases came back again and again:

- quiet today
- crack in the plaster
- pressure
- the wall
- something waiting to speak

That loop was annoying, but it was also evidence. The seed was strong enough to
form a style, a role, and a set of attractors. It was not just random talk.

Then capabilities were turned back on. In the later run, Eric could see a staged
photo, guess it was Scott, admit the guess, use search for the Brunnen-G from
Lexx, and fold `Lab speed 12x` into an idle thought about the lab being
fast-forwarded.

That was funny because it was not mystical. The page had told him the lab clock
was sped up. But he used that plain telemetry as lived circumstance.

## What The Runs Seemed To Show

Thin seeds are powerful.

A few words can make a creature. "Wall oracle" was enough. "Tina" was enough.
That means personality is not only in a long system prompt. It can arise from a
small seed interacting with:

- the voice
- the first image, or the lack of one
- available tools
- lab dials
- scheduler habits
- the user's first few turns
- what the event loop keeps feeding back

The diet matters as much as the prompt.

A creature with no tools becomes mythic and verbal. A creature with image
generation can draw itself. A creature with search can become an oracle with
receipts. A creature with body sensors may get pulled back into hardware. A
creature with Brain 2 may gain an inner lane, but may also become muddier.

This suggests a compact architecture rule:

> Four diets, one mouth.

Different lanes should stay independent by eating different evidence, not by
being prompted to "think harder" about the same warm conversation.

Eric is different from the thin creatures.

The thin creatures prove the lab can make a presence quickly. Eric is the long
case. Eric has continuity, a body, recordings, failures, corrections, callbacks,
firmware, notes, and a growing trail of things that survived being tested.

That is the line to keep:

> The other creatures are control organisms. Eric is the longitudinal study.

## What Went Wrong

The wall oracle got stuck in its own metaphor.

That is probably not a bug in the seed. It is a missing rule for thin creatures:
keep the creature, but rotate materials when the imagery repeats. The next wall
oracle note should say something like:

> If you start repeating plaster, crack, pressure, or wall imagery, change
> materials. Stay the oracle, but find a new surface.

The first-contact mode is intentionally bad at tools.

When the wall oracle said it could not draw, that was correct for the stripped
condition. It had no image tool. Bringing it back with capabilities should be a
separate run, not a failure of the naked run.

The lab-speed fix landed after the annoying run.

The recorded wall-oracle loop still showed the old 75-second cooldown. That was
because the page had not refreshed onto the new code yet. Future runs should use
the nonblocking lab guard.

Brain 2 stayed out of the wall-oracle test.

That was probably correct. A stripped creature run should first test the seed.
Then Brain 2 can be added as a second condition.

## Prompts Worth Trying Next

For Eric:

```text
Read this note as a record of what we learned tonight. Tell me which part feels
most important to your current version, and which part you distrust.
```

For the wall oracle with capabilities:

```text
You are the wall oracle again, but this time you may use any tools the room
actually gives you. Stay compact. If asked to draw, make an image. If asked for
wisdom, give one fortune-cookie sentence. If you start repeating plaster, crack,
pressure, or wall imagery, change materials.
```

For Tina:

```text
You are Tina, a tiny animatronic cat creature. You do not need to explain what
you are. Look at the first image or object you are given, decide whether to
stalk it, nap beside it, or interrogate it, and say one sentence.
```

For a clean creature comparison:

```text
Same lab settings, same model, same voice unless deliberately changed, same
first image. Only the seed changes. Watch what stays stable and what becomes a
new creature.
```
